# STEP3｜著者・監修者の登録（垣谷さん向け）

**この作業は Claude Code ではなく、Shopify の管理画面で手作業で行ってください。**

理由：著者データ（メタオブジェクト）は `claude-seo` の書き込み権限から意図的に外しています。定義を壊すと全記事の表示に波及するためです。ただし**管理画面からの手作業なら問題ありません**。頻度も低い（著者は数人・一度書けば終わり）ので、手で入れるのが一番安全で速いです。

`設定` > `カスタムデータ` > `メタオブジェクト` > **`記事著者`**

## 3. フィールドの一覧

| フィールド | キー | 型 | 記事ページでの出方 |
|---|---|---|---|
| 名前 | `name` | 1行テキスト | 著者カードの見出し。ここが空だと著者カード自体が出ません |
| 肩書き | `role_title` | 1行テキスト | 名前の右に小さく（例：マンマボーノ代表） |
| 顔写真 | `photo` | ファイル | 著者カード左側に 80×80 の画像 |
| 保有資格 | `qualification` | 1行テキスト | 名前の下に1行 |
| プロフィール | `bio` | 複数行テキスト | 資格の下に本文。改行はそのまま反映されます |
| プロフィールページURL | `profile_url` | URL | **画面上には出ません。**構造化データの `Person.url` に出力 |
| SNS・外部プロフィール | `same_as` | URLのリスト | **画面上には出ません。**構造化データの `Person.sameAs` に出力（複数可） |
| ふりがな | `name_kana` | 1行テキスト | **著者ページだけ**に氏名の下に小さく出る（記事下のカードには出ない） |
| プロフィール（著者ページ用） | `long_bio` | リッチテキスト | **著者ページ `/pages/author/◯◯` の本文。**見出し（H2）＋段落で書く。空なら `bio` が代わりに出る |

**入力のコツ**

- **顔写真**：正方形で用意してください（80×80で表示、Retina用に160pxで読み込み）。元画像は 400×400 程度あれば十分です。人物は中央に。アップロードはフィールドの「ファイルを選択」からそのまま可能です
- **保有資格**：西川さんの既存データが `犬の管理栄養士 / 犬の腸活管理アドバイザー / 犬猫アレルギー管理アドバイザー` という **半角スラッシュ＋前後スペース区切り**なので、追加する人もこの書式に揃えてください
- **プロフィール**：資格の羅列は `qualification` に任せて、こちらには**実体験（飼育歴・開発への関与年数・現場で何を見てきたか）**を書いてください。構造化データにも `description` として出力されます

## 5. 獣医師を新規追加する

`記事著者` の画面右上「エントリーを追加」から作成します。

- `name`：氏名
- `role_title`：例）`◯◯動物病院 院長`

## 6. 記事に紐付ける

- `custom.supervisor`（監修者）

未設定の記事は「マンマボーノ編集部」と表示されます。

## 7. 🔴 やらないでほしいこと

- **`記事カテゴリ`（`article_category`）のハンドルを変更・削除しない。**
  こちらはハンドルがそのまま記事のタグ・URL と突き合わされる仕組みです（`sections/c_article.liquid` がタグとハンドルの一致でカテゴリを判定）。1文字変えるだけで、そのカテゴリの記事が一覧から全部消え、カテゴリページのURLも変わります
- **既存の著者エントリーを削除しない。** 参照している記事の著者表示が消えます。名前を直したい場合は削除せず上書きしてください
- **メタオブジェクトの「定義」（フィールドの追加・削除・型変更）は触らない。** 定義の変更は全記事に波及します。フィールドを足したい場合は宮川へ
- メタオブジェクトを**編集したら changelog に1行**残してください（STEP2と同じ書式）。管理画面の変更も Git では追えないので同じ扱いです

## 8. SNS・外部プロフィールの入れ方（2026-08-17 実装済み）

- **`profile_url`**：著者本人の紹介ページを1つ。会社の代表者紹介ページなど
- **`same_as`**：SNSや外部の経歴ページ。「値を追加」で**複数入れられます**（X / Instagram / 掲載記事 など）

どちらも**記事ページの見た目には出ません。**構造化データ（`Person.url` / `Person.sameAs`）にだけ出力されます。

🔴 **同一人物を指すURLだけを入れてください。**`sameAs` は「この人物の別の所在」を宣言するプロパティなので、商品ページや無関係な自社ページを入れると誤った宣言になります。

**監修者（`reviewedBy`）にも同じフィールドがそのまま出力されます。**保有資格（`qualification`）も 2026-08-17 に出力対象へ追加したので、獣医師監修の記事では `qualification` に「獣医師」を入れておけば、構造化データにも資格として出ます。

出力例（実機で検証済み）：

```json
"author": {
  "@type": "Person",
  "name": "西川友保",
  "jobTitle": "マンマボーノ代表",
  "description": "犬の管理栄養士 / 犬の腸活管理アドバイザー / 犬猫アレルギー管理アドバイザー",
  "url": "https://manmabuono.jp/pages/about",
  "sameAs": ["https://www.instagram.com/manmabuono/", "https://x.com/manmabuono"]
}
```

※ 上記URLは動作検証に使ったダミーです。実際の値は未入力なので、正しいURLを入れてください。

## 9. 著者プロフィールページ（2026-08-17 実装済み）

**著者を1件登録すると、そのページが自動で生えます。** 固定ページを作る必要はありません。

- URL：`https://manmabuono.jp/pages/author/{ハンドル}`
  - 例）西川さん → https://manmabuono.jp/pages/author/nishikawa
- 表示内容：顔写真・氏名・肩書き・保有資格・プロフィール文＋「マンマボーノの思い」へのリンク
- **記事下の著者カードと同じデータ（このメタオブジェクト）を見ています。** 管理画面の1箇所を直せば、記事側とページの両方に反映されます（二重管理になりません）
- 構造化データは `ProfilePage` + `Person` を出力。記事側の `author` / `reviewedBy` と同じ部品を使っています

### 🔴 プロフィール文（`bio`）が空のページは noindex になります

エントリーを作った瞬間にURLが生えるため、氏名と肩書きだけの中身の薄いページが検索に載らないよう、**`bio` が空のあいだは自動で `noindex` が付きます。**`bio` を入れれば自動的に index に戻ります（こちらの作業は不要です）。

そのため、**獣医師を追加するときは `bio` まで入れてください。**名前だけ登録して放置すると、そのページは検索に載らないままになります。

### `profile_url` に入れる値

このページができたので、`profile_url` にはこのページのURLを入れてください。

- 西川さん（`nishikawa`）→ `https://manmabuono.jp/pages/author/nishikawa`
- 以降に追加する著者も同じ形（`/pages/author/{そのエントリーのハンドル}`）

`same_as` は従来どおり、**ご本人個人**のSNSや外部の経歴ページを入れてください。
