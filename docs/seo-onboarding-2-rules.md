# STEP2｜記事を書くときのルール（垣谷さん向け）

STEP1（接続）が終わってから読むもの。**Claude Code にそのまま読ませてください。**

テーマ側の実装と噛み合っているルールなので、外すと「カテゴリページに出ない」「目次が出ない」「meta description が空になる」といった不具合になります。

---

## 1. 権限の範囲

`claude-seo` は**書き込みが記事とファイル（画像）だけ**で、それ以外は読み取り専用にしてあります。

| できる | できない |
|---|---|
| 記事の作成・更新・記事のメタフィールド設定 | テーマの閲覧・編集 |
| 画像のアップロード | 商品の編集（商品SEOの書き換え含む） |
| 商品・在庫・コレクションの**閲覧** | メタオブジェクト（著者・カテゴリ）の追加・編集・定義変更 |
| 売上レポート（ShopifyQL）の**閲覧** | 注文・顧客データの閲覧 |
| 著者・カテゴリのメタオブジェクトの**閲覧** | |

商品・在庫・売上が読めるようにしてあるのは、**記事の内部リンクやCTAの設計、ネタ選定を自分で調べられるように**するためです。遠慮なく読んでください。

書き込みを絞っているのは信用の話ではなく、**Shopify 側に「何をどう書き換えたか」の差分ログが残らない**からです。Dev Dashboard の API ログはエンドポイントと回数のレベルまで、記事にバージョン履歴もありません。事後に追えない以上、事前に閉じておくしかない、という設計です。

権限エラーが出たら**回避策を探さず宮川に連絡してください。**必要なら足します。

> これは API（Claude Code）からの話です。**著者メタオブジェクトの登録・編集は、管理画面から手作業で行っていただいて構いません** → STEP3（`seo-onboarding-3-author.md`）。手作業なら一括で壊れる心配がなく、頻度も低いためです。

## 2. 記事を1本出すまでの流れ

1. **下書きで作る。**いきなり公開しない
2. 管理画面 or プレビューで確認
3. 公開
4. 記事下のおすすめ商品（CTA）を設定する（下記）

### 記事下のおすすめ商品（CTA）は自分で設定できます

記事メタフィールド **`custom.related_products`**（商品参照・リスト）に商品を入れれば、記事下に商品カードが最大3件出ます。**これは記事のメタフィールドなので `claude-seo` の権限内です。宮川への依頼は不要です。**

- `custom.related_collection`（コレクション参照）も同様に設定可。商品を指定しない記事のフォールバックとして、コレクションカードが出ます
- 例外：**商品ごとに記事の文脈に合わせた「一言」を添えたい場合のみ宮川へ。**この場合だけ別のメタオブジェクト（`product_recommendation`）が必要で、そこは書き込み権限を外してあります。一言なしの通常運用は上記で完結します

### 🔴 既存記事を更新する前に、現在の内容を退避する

記事にバージョン履歴はありません。**上書きしたら戻せません。**

```python
before = gql('query($id: ID!) { article(id: $id) { id title handle body summary tags } }',
             {"id": "gid://shopify/Article/..."})
open("backup/article_xxx.json", "w").write(json.dumps(before, ensure_ascii=False, indent=2))
```

### 書き込んだら1行残す

上と同じ理由（差分ログが残らない）で、**書き込み系の操作をしたら記録を残してください。**
記録は**宮川に共有**してください（テーマのリポジトリは共有していないため、こちらで `docs/admin-changelog.md` に転記します）。都度でも週まとめでも構いません。

書式：`- 日付 | 対象 | 何を | 手段 | 復元手段`

例：
```
- 2026-08-20 | article「シニア犬の食欲不振」 | 導入とH2見出し3本を改稿（検索意図とのズレ） | 自前スクリプト | 復元: backup/article_xxx.json
```

## 3. 記事の書き方ルール

- **ブログは `column`（`/blogs/column`）／テンプレートは `column` を選ぶ**
- **カテゴリタグを必ず1つだけ**付ける。2つ以上付けると最初に一致したものがカテゴリ扱いになります
  `choose` / `trouble` / `feeding` / `health` / `storage` / `basics` / `homemade`
- **自由タグ**は複数OK：`cat` `dog` `kitten` `puppy` `senior` `dry` `wet`
- 🔴 **タグは必ず半角英字。**日本語タグは URL が文字化けします
- 🔴 **抜粋（excerpt）は必ず書く**（80字前後）。一覧カードと **meta description** に使われます
- **アイキャッチ**：16:9 推奨・横1200px以上
- **見出しは H2 → H3 の順**（目次が H2/H3 から自動生成されます）
- **著者・監修者**：記事メタフィールド `custom.author` / `custom.supervisor` にメタオブジェクト `article_author` を紐付け。未設定だと「マンマボーノ編集部」表示になります。**著者そのものの登録・編集は管理画面での手作業**です → STEP3（`seo-onboarding-3-author.md`）
- 記事内で使える HTML パーツは下記 §6 にあります

**新しいカテゴリを追加したいときは宮川へ。**メタオブジェクトの書き込み権限を外してあるので API からは作れません（カテゴリはハンドルがそのままタグ・URL になり、変更が全記事に波及するため）。
**著者・監修者の追加は管理画面から手作業でできます**（STEP3 参照）。

## 4. テーマ側は実装済みなので触らない

以下は**もうテーマに入っています**。記事側でやり直さないでください。

- 記事の構造化データ（Article ＋ BreadcrumbList。著者の資格、監修者は reviewedBy）
- パンくず（TOP > コラム > カテゴリ > 記事）
- カテゴリページの title / description 差し替え
- タグ絞り込みページの `noindex, follow`（重複コンテンツ対策）
- 目次の自動生成（H2/H3 から）

ここを変えたい・足したい場合は宮川に言ってください。テーマは Git 管理で main への push が即・本番反映なので、二重に実装されると事故ります。

## 5. やらないでほしいこと（まとめ）

- テーマ（`.liquid` / CSS / 構造化データ）を触る
- いきなり公開する
- 既存記事を退避せずに上書きする
- 商品ページの SEO を書き換える（依頼は宮川へ。売上に直結するため）
- シークレットをチャット・メール本文・Git に平文で置く

## 6. 記事内に貼れる HTML パーツ

記事エディタの `<>`（HTMLを表示）モードで貼り付けてください。
CSS はテーマ側に実装済みです。**クラス名は変えない・独自の `style` 属性は足さない**（崩れます）。
ここに無い型（比較表・FAQアコーディオン等）が欲しくなったら宮川へ。テーマ側に足します。

### ポイントボックス

```html
<div class="ca-box">
<p class="ca-box__title">ポイント</p>
<p>ここに本文を書く</p>
</div>
```

### 注意ボックス

```html
<div class="ca-box --warn">
<p class="ca-box__title">注意</p>
<p>ここに本文を書く</p>
</div>
```

### メモボックス

```html
<div class="ca-box --memo">
<p class="ca-box__title">メモ</p>
<p>ここに本文を書く</p>
</div>
```

### 吹き出し

画像は「コンテンツ > ファイル」にアップロードして URL をコピーしてください。

```html
<div class="ca-balloon">
<div class="ca-balloon__icon"><img src="画像URL" alt="編集部"></div>
<p class="ca-balloon__text">セリフをここに書く</p>
</div>
```

### CTAボタン

```html
<a class="ca-btn" href="/collections/コレクションのハンドル">おすすめフードを見てみる</a>
```
