# サブスク（三河屋サブスクリプション）の仕組みと `［追加用］` 商品

> 調査日: 2026-07-31（Shopify実データ＋三河屋サポートとのメール履歴＋アプリJS解析）
> 対象読者: この店のサブスク周りを触る人。**商品の価格を変える前・新商品を出す前に必ず読む。**

---

## 0. 3行まとめ

- サブスクは **三河屋サブスクリプション**。販売プラングループ `定期購入` ＝ **10% OFF・配送頻度1種**、公開商品31件に紐付く。
- **`［追加用］` 商品（32件・非公開）は、顧客がマイページから定期便に商品を「追加」するとき専用の、10%引き価格を直接設定した商品。** アプリの仕様上「追加」では割引が引き継がれないため、この受け皿が要る。
- **保守は完全に手動。** 通常版の価格を変えたら追加用も変える必要がある。**過去に実際3商品で漏れていた**（2026-08-01 修正済み → §4）。**価格を触ったら必ず `python3 scripts/check_addon_prices.py` を回すこと。**

## 1. なぜ `［追加用］` が要るのか（三河屋サポートの公式回答）

メール履歴（2025年・宮川 ⇄ Mikawayaサポート）より：

> **商品追加機能は割引率が引き継がれない仕様となっております。**
> 「**変更**」で操作された際は、サブスクリプショングループで設定している割引が引き継がれます。
> 「**追加**」で操作された場合は、引き継がれず定価の価格の表示となります。
>
> 商品「追加」の際に、割引後の価格を適用させたい場合は、**Shopify商品管理にて商品追加機能で設定する専用商品を別途作成**いただく必要がございます。
> 作成時に、**価格も割引後の価格（10％OFF後の価格）で用意**いただき（略）

補足（同じくサポート確認済み）：「**変更**」画面では割引前価格が表示されるが、**実際に変更操作を行うと割引後価格が適用される**。表示だけの話なので不具合ではない。

出典: https://mikawayahelp.oopy.io/08c33d25-7f82-4d1e-92d1-1c68dc22d8ba

## 2. 運用チェックリスト（サポートが「ご認識の通り」と確認）

この4つが `［追加用］` 方式の保守コスト。**忘れるとそのまま損失になる。**

1. サブスク商品の **追加用を割引後価格で全て作成** する
2. **価格が変更になったときに追加用も一緒に変更** する
3. **在庫切れになった時に非アクティブにする**
4. **新しくサブスク商品ができたら追加用も同時に作成** する

## 3. どこで登録するか＝アプリ側の設定（Shopifyではない）

- Mikawaya管理画面の **「設定」⇒「マイページ追加購入設定」⇒「対象の商品を追加」**。ここで選んだ商品**だけ**が、顧客のマイページの「**追加で商品を購入**」に出る。
- **これはアプリ側のデータで、Shopify Admin API からは読めない。** 「今の追加用が実際に効いているか」を確かめるには、**この画面を開いて登録状況を見るしかない**。
- マイページ本体は **App Proxy `/apps/floor-s`**（floor-s ＝三河屋の開発元）。中身は三河屋側の Next.js アプリで、テーマのLiquidは一切関与しない。テーマ側にあるのは入口リンク3箇所だけ（`sections/main-account.liquid` / `snippets/header-drawer.liquid` / `sections/footer.liquid`）。
- 商品一覧の取得API（クライアントから叩かれる。未認証だと401）：
  - `GET /apps/floor-s/api/v1/my-page-target-product-variants?offset&limit`
  - `GET /apps/floor-s/api/v1/my-page-target-group-product-variants?sellingPlanGroupId&sellingPlanGroupIds`
- 🔑 **重要な帰結**：この一覧は **Shopifyのコレクションもその並び順も参照していない**。
  - → **コレクションの並び替え（dog-all / cat-all）はマイページの追加画面に影響しない。**
  - → `［追加用］` を非公開（UNLISTED）のままにできるのもこれが理由。店頭には出ないが、アプリに登録されていれば追加画面には出る。
  - → **追加画面の並び順を変えたいならアプリ側で操作する**（Shopify側からは動かせない）。並び替え機能の有無は未確認。

## 4. 現状（2026-07-31 実データ）と **要修正リスト**

Shopify側の基本状態は正常：**`［追加用］` 32件すべて `UNLISTED` かつ `availableForSale: true`**（＝店頭に出さず、追加画面から購入できる状態）。29件は通常版のちょうど90%。

### ✅ 解決済み（2026-08-01）

- [x] **プレミアム料理3種の `［追加用］` 価格を10%OFFに修正した。**（¥1,210→**¥1,089** / ¥1,430→**¥1,287** / ¥1,320→**¥1,188**）
  - **原因＝作業の途中放置**。2026-05-11 に Shopify で商品を複製し（handle が `-コピー` で終わっているのが痕跡。正常な29件は `-追加用`）、タイトルに `［追加用］` を付けたところで止まり、**価格変更をしていなかった**。UNLISTED・プランなし・在庫0 という他の設定は正しく揃っていた。
  - 手段＝`scripts/check_addon_prices.py --fix`／復元＝`scripts/collection_order/addon_prices.backup.json`
  - handle の `-コピー` → `-追加用` リネームは**あえてしていない**（三河屋は variant ID で参照しており機能影響が無いため、見た目の統一のためにURLを動かすリスクを取らない判断・2026-08-01）。
  - 🔁 **再発防止＝`scripts/check_addon_prices.py`**（引数なしで点検のみ）。全 `［追加用］` が「通常版×0.9」になっているか一発で検査できる。**価格改定のたびに必ず回す。**
